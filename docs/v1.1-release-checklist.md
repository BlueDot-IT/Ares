# Ares 1.1 Release Checklist

This checklist is the release gate for Ares 1.1.0.

## Product identity

- [ ] `pyproject.toml` project name is `bluedot-ares`.
- [ ] `pyproject.toml` version is `1.1.0`.
- [ ] `src/ares/__init__.py` version is `1.1.0`.
- [ ] The package imports as `ares`.
- [ ] The installed commands are `ares`, `ares-dashboard`, and `ares-tui`.
- [ ] Documentation warns that the PyPI project named `ares` is unrelated.

## Runtime and policy

- [ ] Full test suite passes from a clean checkout.
- [ ] Python 3.11, 3.12, and 3.13 CI passes.
- [ ] Windows wheel smoke testing passes.
- [ ] `ares doctor --json` returns valid JSON.
- [ ] `ares support-bundle` writes a valid redacted JSON document.
- [ ] `ares mission run --help` exposes `--approval-receipts`.
- [ ] Governed autonomous reconnaissance remains passive and safe-active only.
- [ ] Advanced roles remain operator-supplied and receipt-gated.
- [ ] Cross-target and cross-mission evidence tests pass.
- [ ] StateDB migration and reopen tests pass.

## Package gate

Run from a clean checkout:

```bash
git checkout main
git fetch origin --prune
git reset --hard origin/main
git clean -fdx -e vendor/ghostmcp

git submodule update --init --recursive

python -m venv .venv-release
. .venv-release/bin/activate
python -m pip install --upgrade pip build twine cyclonedx-bom==7.3.0
python -m pip install -e '.[dev,anthropic,gemini,ghostmcp]' -e vendor/ghostmcp

python -m pytest tests -q
python -m compileall -q src/ares

git diff --check
rm -rf dist build src/*.egg-info
python -m build
python -m twine check dist/*
```

Verify artifact names:

```bash
test -n "$(find dist -maxdepth 1 -name 'bluedot_ares-1.1.0-py3-none-any.whl' -print -quit)"
test -n "$(find dist -maxdepth 1 -name 'bluedot_ares-1.1.0.tar.gz' -print -quit)"
```

## Isolated wheel gate

```bash
python -m venv /tmp/ares-1.1-wheel
. /tmp/ares-1.1-wheel/bin/activate
python -m pip install --upgrade pip
python -m pip install dist/bluedot_ares-1.1.0-py3-none-any.whl

test "$(ares --version)" = "1.1.0"
python -c "import ares; assert ares.__version__ == '1.1.0'"
python -c "import importlib.metadata as m; assert m.version('bluedot-ares') == '1.1.0'"
ares doctor
ares doctor --json | python -m json.tool
ares support-bundle --out /tmp/ares-support-bundle.json
python -m json.tool /tmp/ares-support-bundle.json
ares dashboard --help
ares-dashboard --help
ares tui --help
ares mission run --help | grep -F -- '--approval-receipts'
ares route --target 127.0.0.1 --prompt "safe local smoke test"
ares training --out /tmp/ares-sft-smoke.jsonl --min-status final_response
```

## Security gate

- [ ] `git diff --check` passes.
- [ ] Gitleaks passes with redaction enabled.
- [ ] Ruff critical defect rules pass.
- [ ] Bandit high-severity gate passes.
- [ ] `pip-audit` passes or every exception is documented and explicitly accepted.
- [ ] No credentials, approval receipts, engagement policies, or customer evidence are in the diff or history.
- [ ] Release workflow contains no long-lived PyPI token secret.

## Documentation gate

- [ ] README matches the released command surface.
- [ ] `CHANGELOG.md` changes `Unreleased` to the release date.
- [ ] `docs/releases/v1.1.0.md` matches final behavior.
- [ ] `docs/v1-support-boundary.md` matches final behavior.
- [ ] Installation, migration, support, troubleshooting, and verification docs are accurate.
- [ ] GitHub issue forms and PR template render correctly.

## PyPI Trusted Publishing setup

Before the first publication:

- [ ] Reserve or create the `bluedot-ares` project through a PyPI pending trusted publisher.
- [ ] Configure owner `BlueDot-IT`.
- [ ] Configure repository `Ares`.
- [ ] Configure workflow `.github/workflows/release.yml`.
- [ ] Configure GitHub environment `pypi`.
- [ ] Add required reviewers to the `pypi` environment if desired.
- [ ] Set repository variable `PYPI_PUBLISH_ENABLED=true` only after the publisher is verified.
- [ ] Confirm there is no `PYPI_API_TOKEN` secret.

The workflow refuses PyPI publication outside `BlueDot-IT/Ares` and remains disabled when the repository variable is absent or false.

## Tag and release

Update the changelog date, commit the release identity, and create an annotated tag:

```bash
git tag -a v1.1.0 -m "Ares v1.1.0"
git push origin v1.1.0
```

Never move an existing release tag. Resolve any tag or package identity conflict with a new version.

The tag workflow must:

- [ ] verify tag, package, and runtime versions
- [ ] run tests and compile checks
- [ ] build and validate wheel and source distribution
- [ ] smoke-test the installed wheel
- [ ] generate a CycloneDX SBOM
- [ ] generate `release-metadata.json`
- [ ] generate `SHA256SUMS`
- [ ] create build provenance attestations
- [ ] create SBOM attestations
- [ ] publish the GitHub release
- [ ] publish to PyPI only through the gated trusted publisher job

## Post-release verification

```bash
mkdir -p /tmp/ares-release-verify
cd /tmp/ares-release-verify
gh release download v1.1.0 --repo BlueDot-IT/Ares
sha256sum -c SHA256SUMS
gh attestation verify bluedot_ares-1.1.0-py3-none-any.whl --repo BlueDot-IT/Ares
```

Then test a clean public install:

```bash
pipx install bluedot-ares==1.1.0
ares --version
ares doctor --json
```

- [ ] GitHub release contains all expected assets.
- [ ] PyPI metadata, provenance, links, and classifiers are correct.
- [ ] Public installation does not resolve the unrelated `ares` distribution.
- [ ] Release notes and changelog links resolve.
