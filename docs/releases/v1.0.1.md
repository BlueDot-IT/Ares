# Ares v1.0.1 Release Notes

Ares v1.0.1 is a security and reliability patch for the supervised operator runtime.

## Security fixes

- Evidence-memory search is now constrained to the current engagement target. Earlier sessions for the same target remain available, but unrelated targets cannot bleed into model context.
- Gateway dangerous approvals require an authenticated gateway session even when ordinary safe endpoints are configured for unauthenticated loopback use.
- Approval audit records include a non-secret session fingerprint and authentication source. Bearer tokens are never written to the audit log.
- GhostMCP engagement identifiers, execution mode, and authorization tokens are injected only by trusted runtime context and are no longer model-visible parameters.

## OAuth fixes

- Expired OpenAI OAuth sessions refresh silently using the cached refresh token.
- Refresh-token rotation is preserved atomically; providers that do not return a replacement retain the existing refresh token.
- Refresh failures direct the operator to `ares auth login openai`.
- Background model execution never opens an interactive browser login.

## Runtime and operator experience

- `run_agentic()` now fails closed because genuine model-driven mission planning is not implemented. The former deterministic behavior is available as `run_contextual_deterministic()`.
- Gateway and dashboard bind failures now produce concise, actionable errors without Python tracebacks.
- Windows installs load the main CLI normally and install the platform-specific curses compatibility package for the TUI.
- State and private-file initialization now uses portable permission handling on Windows while retaining restrictive POSIX modes.
- Package metadata and project links identify the canonical `BlueDot-IT/Ares` repository.

## Release artifacts

The `v1.0.1` tag workflow verifies that the tag matches package metadata, builds the wheel and source distribution, smoke-tests the installed wheel, and publishes both artifacts to the GitHub release.
