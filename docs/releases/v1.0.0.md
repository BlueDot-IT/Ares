# Ares v1.0.0 Release Notes

Ares v1.0.0 is the first stable release of the operator-supervised Ares security testing runtime for authorized engagements.

## Positioning

Ares is a supervised operator platform. It is not an unattended autonomous assessment product. The model can reason and request tools, but Ares keeps scope, risk, approval gates, routing, persistence, evidence recall, and reporting outside the model.

Authorized testing only.

## Highlights

- Stable package metadata and runtime version: `1.0.0`.
- Stable command surface through `ares`.
- Distinct operator surfaces:
  - `ares gateway` for the HTTP API/control plane.
  - `ares dashboard` and `ares-dashboard` for the browser dashboard.
  - `ares tui` and `ares-tui` for the terminal operator UI.
- Gateway auth, pairing codes, CIDR allowlists, run status, event polling, and audit logging.
- Browser dashboard backed by the gateway API and served at `/` and `/dashboard` for bundled local use.
- Multi-provider model adapters and fallback chains.
- OpenAI and Gemini OAuth helpers.
- Dispatcher-owned policy choke point for scope, ROE, risk, approval, duplicate suppression, target-route policy, and timeouts.
- Compact and long-context modes.
- SQLite-backed state with stable v1 schema metadata and beta database upgrade handling.
- Evidence memory chunks with FTS5 search and LIKE fallback.
- Passive evidence recall tools.
- Redacted training-data export.
- Markdown reports.
- Security policy and v1 support boundary.

## Installation

```bash
git clone https://github.com/BlueDot-IT/Ares.git
cd Ares
git checkout v1.0.0
git submodule update --init --recursive

python -m venv .venv
. .venv/bin/activate
python -m pip install -e .
```

Optional extras:

```bash
python -m pip install -e '.[dev]'
python -m pip install -e '.[anthropic]'
python -m pip install -e '.[gemini]'
python -m pip install -e '.[ghostmcp]'
```

## Final validation before tagging

Run from a clean checkout:

```bash
git checkout main
git fetch origin --prune
git reset --hard origin/main
git clean -fdx -e vendor/ghostmcp

git submodule update --init --recursive

python -m venv .venv-v1
. .venv-v1/bin/activate
python -m pip install --upgrade pip build
python -m pip install -e '.[dev,anthropic,gemini,ghostmcp]' -e vendor/ghostmcp

python -m pytest tests -q
python -m compileall src/ares

rm -rf dist build src/*.egg-info
python -m build
python -m pip uninstall -y ares
python -m pip install dist/ares-1.0.0-py3-none-any.whl

ares --version
ares doctor
ares tools
ares dashboard --help
ares-dashboard --help
ares route --target 127.0.0.1 --prompt "safe local smoke test"
ares training --out /tmp/ares-sft-smoke.jsonl --min-status final_response
```

## Tagging

After the final validation passes, create the tag if it does not already exist:

```bash
git tag -a v1.0.0 -m "Ares v1.0.0"
git push origin v1.0.0
```

Never move a published release tag. If the tag exists at the wrong commit,
publish a new patch version with an accurate tag and document the superseded
artifact.

GitHub Actions will build package artifacts on tag push through `.github/workflows/release.yml`.
