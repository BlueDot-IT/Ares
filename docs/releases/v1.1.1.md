# Ares v1.1.1

Ares v1.1.1 is a reliability and repository-security patch for the operator-supervised security assessment runtime.

## Fixed

- Deterministic and contextual-deterministic missions now close operator runs and backing sessions accurately on success, failure, blocked work, and unexpected errors, including tasks that do not invoke a tool.
- New executions no longer leave those records marked as `running` after mission work has ended.
- The release workflow now selects `docs/releases/<tag>.md` for the exact verified release instead of reusing v1.1.0 notes.

The lifecycle fix does not rewrite historical state. Back up `~/.ares` before separately reconciling stale records created by an earlier version.

## Security and release hardening

- CodeQL now analyzes Python changes on pull requests, pushes to `main`, a weekly schedule, and manual runs.
- GitHub private vulnerability reporting is enabled, aligning the repository setting with `SECURITY.md`.
- The nonfunctional repository-local scheduled Codex Security workflow was retired. Durable organization-level Codex Security scanning remains a separate operational task.
- Optional PyPI publication remains restricted to `BlueDot-IT/Ares`, gated by `PYPI_PUBLISH_ENABLED`, protected by the `pypi` environment, and authenticated with GitHub OIDC Trusted Publishing.

## Upgrade and verify

Back up `~/.ares`, install `bluedot-ares==1.1.1` in an isolated environment, and run:

```bash
ares --version
ares doctor --json
sha256sum -c SHA256SUMS
gh attestation verify bluedot_ares-1.1.1-py3-none-any.whl --repo BlueDot-IT/Ares
```

See [installation](../../INSTALL.md), [the support boundary](../v1-support-boundary.md), and [release verification](../verifying-releases.md).
